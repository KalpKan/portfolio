## Known limitations that are NOT defects

- **Google account pick cannot be automated from this harness.** The chooser is a separate Chrome window outside the extension's tab group and AppleScript JavaScript is disabled in Chrome; the full round trip on this host was proven by the Phase 2–4 audit (real Chrome, `water_now_clicked` 2026-09-18 23:26 UTC). This round additionally proved the **cancel** path (close the popup → "Sign-in was cancelled…", button re-enabled, no console error). Two stale chooser windows (one from round 1) were closed.
- **The claude-in-chrome window is shared** with another agent's tab (emotes) and refused the 390 px resize; the phone width was measured with Playwright.
- **Production could not be updated this round** (D14); the `fad7516` measurements come from a local stack that uses the real Firebase, Supabase and Pl@ntNet and the production build with the production PostHog key, with only the spend counter in memory and no CDN in front.
- **A valid visitor OpenAI key was not tested** ($0 rule: no key to spend); the invalid-key path is proven end to end.
- **Hardware-required calls print the browser's own "Failed to load resource: 502 / 400"** lines; the app raises nothing.
- **A deleted photo keeps serving from Supabase's CDN for a short time** (200 at 1.5 s after delete); the object is gone.
- **Dark theme only** (`mode: 'dark'` hard-coded), so "both themes" collapses to one; `prefers-color-scheme: light` was set on the phone context and changes nothing.
- **Pl@ntNet budget:** 50 identifications per UTC day on the hosted app (40 used at 03:10 UTC); running the corpus against production would exceed it today, hence the local stack (0 on the counter).
- **Photos added before 2026-09-18** (Firebase Storage on Spark) show the labelled "Photo no longer available" placeholder by design.
