# Pushup form tracker in the browser (T3.1) — design

_2026-09-18. Self-contained brainstorm (Kalp is not watching): each design question is written with the answer chosen and why. Path: **architectural** (new codebase)._

## What exists

- `KalpKan/AI-Pushup-Form-Tracker` (public, 459 MB pack): Python scripts. `test_pushup_form.py` / `scripts/real_time_pushup_form.py` = MediaPipe legacy `mp.solutions.pose` → 12 landmarks (L/R wrist, elbow, shoulder, hip, knee, ankle) × (x, y, z) = 36 floats → Keras MLP `model/pushup_model_augmented.h5` (Sequential 128→64→32→1 sigmoid, dropout in training) → Good/Bad per frame → shoulder-height rep state machine (dynamic min/max, 10 % bands, 10-frame warm-up, a rep counts only if the form was Good at the top **and** at the bottom).
- Training (`scripts/train_model.py`) fits a `StandardScaler` on the 80 % train split of `outputs/pushup_keypoints_augmented.csv` (`train_test_split(test_size=0.2, random_state=42)`) and trains on the **scaled** features. The scaler was never saved. The inference scripts feed **raw** landmarks to the model (a latent bug in the original; the model expects scaled inputs).
- Local newer copy: `/Users/kalp/Desktop/Out and About/Sidequest/AI_Pushup_Tracking/` (read-only) has the same scripts plus a 131 MB demo mp4 and the raw training videos; nothing there changes the design.
- Big files in the repo HEAD: `outputs/*.csv` (156 MB), `model/pushup_form_classifier.pkl` (64 MB RandomForest, unused by the tracker), `test_video/*.mp4` (~150 MB). ~230 MB of history is video/CSV/pkl.

## Design questions and answers

1. **Pose estimation in the browser: legacy `@mediapipe/pose` vs `@mediapipe/tasks-vision` PoseLandmarker?**
   `@mediapipe/tasks-vision` PoseLandmarker, `runningMode: "VIDEO"`, `pose_landmarker_lite.task` (5.5 MB) self-hosted in `public/models/`, the WASM runtime (`vision_wasm_internal.js/.wasm`, ~10 MB) copied from `node_modules/@mediapipe/tasks-vision/wasm` into `public/wasm/` at build. The legacy package is deprecated and pulls from a Google CDN at runtime (violates "no network calls after load"). Landmark convention is the same as the Python solution (normalized x, y in [0,1], z on the same scale), so the 36-float feature vector transfers 1:1. GPU delegate first, CPU fallback.

2. **Form classifier: convert to TF.js or re-implement the MLP in TypeScript?**
   Convert with `tensorflowjs_converter --input_format keras` (task requirement) to `public/models/form/model.json` + `group1-shard1of1.bin` (~55 KB) and run it with `@tensorflow/tfjs` (CPU backend; 13 k weights, a 36-vector every frame is microseconds on CPU and avoids WebGL context contention with MediaPipe's GPU delegate). Loaded lazily with `import()` when a session starts, so it is not on the Lighthouse critical path.

3. **Scaler: raw inputs (like the original real-time script) or StandardScaler (like training)?**
   Decide from evidence, not from the scripts: evaluate the `.h5` on the held-out 20 % split both ways. If the scaled inputs score materially higher, the scaler is what the model expects; recompute `mean_`/`scale_` exactly as training did (same split, same seed) and bake them as constants in `src/scaler.ts` (36 + 36 numbers, generated by `scripts/export_scaler.py`, with the accuracy figures in a comment). The measured numbers go in the README so the choice is auditable.

4. **Rep counting: port verbatim or improve?**
   Port the state machine verbatim (`src/repCounter.ts`, pure function over a stream of `{shoulderY, good}`), because the fixtures compare against the Python reference. One addition that does not change the good-rep count: the machine also emits `{good:false}` when a top→bottom→top cycle completes with bad form somewhere, so the UI can show "attempts" and PostHog gets `rep_counted {good:false}`. The counter returns `{goodReps, totalReps, phase}` and an event list.

5. **What does a visitor without a webcam see?**
   A "Play demo clip" button runs the same pipeline on a bundled clip (`public/demo/pushups.mp4`, ~6 s, 640 px wide, H.264, ≤ 2 MB, trimmed with ffmpeg from `test_video/test_video3.mp4`, which the Python script itself uses as its test). Same code path (`PoseLandmarker.detectForVideo` on a `<video>`), so the demo proves the whole pipeline.

6. **Front camera on phones?**
   `getUserMedia({ video: { facingMode: "user", width: { ideal: 640 } } })`. The preview canvas is mirrored (CSS `scaleX(-1)`) for the camera only; features are computed on the unmirrored frame. Portrait phones: the canvas follows the video's intrinsic size and is scaled with CSS `max-width: 100%`.

7. **Fixtures for unit tests?**
   `scripts/make_fixtures.py` runs the **Python** pipeline (legacy `mp.solutions.pose`, same confidence settings as the inference script) on two short windows of the old repo's test videos, and writes `tests/fixtures/<name>.json`: per frame the 36 features + `shoulderY`, the Keras probability with the baked scaler, and the Python state machine's rep events + final count (the state machine is copied verbatim into the script). Vitest then asserts: TS classifier ≈ Keras (|Δp| < 1e-4 per frame), TS rep counter = Python rep events and counts. No MediaPipe in the browser tests (deterministic, fast, no GPU).

8. **Lighthouse ≥ 0.85 with 15 MB of models?**
   Nothing ML loads until the visitor clicks. Initial page = HTML + CSS + ~5 KB JS + posthog-js (deferred after `load`). WASM, `.task`, TF.js and the model are fetched on the first click with a progress line. Models are served with `Cache-Control: immutable`. Trade-off documented: the first click costs 15 MB (5–10 s on 4G); after that the browser cache makes it instant. Alternative rejected: preloading on page load would score badly and waste data for visitors who only read.

9. **Analytics?**
   posthog-js exactly like microtubules (`/ingest` rewrites in `vercel.json` with `:path(.*)`, cookieless, autocapture, replay with inputs masked). Custom events: `session_started {mode:"camera"|"demo"}`, `rep_counted {good:boolean}`, `demo_video_played`. No landmark or image data, ever (guarded by the `capture()` signature).

10. **Old repo?**
    A branch `purge-data-files` off `main` in the read-only clone (`~/projects/pushups-python`): one commit deleting `outputs/`, `model/pushup_form_classifier.pkl`, `test_video/` (keeps the 220 KB `.h5` and every script), adding `.gitignore` for those paths and a README that explains what the project is and points at https://pushups.kalpkan.com and the new repo. Opened as a PR; **no force-push**, main untouched (history still holds the blobs until Kalp merges and, optionally, runs the "Purge a large file from git history" runbook).

## Architecture (new repo `KalpKan/pushup-tracker-web`, local `~/projects/pushups`)

```
index.html                 static shell: title, two buttons (Start camera / Play demo clip), canvas, stats
src/main.ts                UI wiring; lazy-imports the session module on click
src/session.ts             owns the loop: source (camera|demo) → PoseLandmarker.detectForVideo → features → classifier → repCounter → draw
src/pose.ts                loads FilesetResolver from /wasm + PoseLandmarker from /models/pose_landmarker_lite.task
src/features.ts            LANDMARK_INDEXES (12 MediaPipe ids in the Python order) → 36 floats + shoulderY (pure)
src/scaler.ts              baked MEAN/SCALE constants + scale() (generated)
src/classifier.ts          loads /models/form/model.json with @tensorflow/tfjs, predict(features) → probability
src/repCounter.ts          the ported state machine (pure, testable)
src/draw.ts                skeleton overlay, count, verdict on a canvas
src/analytics.ts           posthog wrapper (3 events)
public/models/, public/wasm/, public/demo/pushups.mp4, public/health.json
scripts/export_model.sh    h5 → TF.js (venv)
scripts/export_scaler.py   CSV → scaler constants + accuracy report
scripts/make_fixtures.py   videos → tests/fixtures/*.json
tests/*.test.ts            features, scaler, classifier-vs-keras, repCounter-vs-python
```

Data flow per frame: `video` → `detectForVideo(video, now)` → `result.landmarks[0]` (33 points) → `features(landmarks)` → `scale()` → `classifier.predict()` → `good = p > 0.5` → `repCounter.push({shoulderY, good})` → draw + emit events.

Error handling: no camera permission → message and the demo button stays; WASM/model fetch failure → message with a retry; no pose in frame → overlay says "Step back so your whole body is visible"; GPU delegate failure → CPU delegate retry.

## Non-goals

No retraining, no accounts, no server, no saving of video, no landmark upload. The model's accuracy is what the 2025 training run produced; the README states its limits (side view, one person, camera roughly at floor level, trained on Kalp's own videos).

## Definition of done (from the task)

Live at https://pushups.kalpkan.com; counts good reps from the webcam on desktop and phone; demo clip works without a camera; no network calls after load except `/ingest`; PostHog 3 events; `health.json`; Lighthouse ≥ 0.85; unit tests on 2 recorded landmark fixtures; PR on the old repo; README with the non-developer section; ops skill runbook "Deploy a browser-ML app (MediaPipe) to Vercel"; STATUS.md and projects.json updated.
