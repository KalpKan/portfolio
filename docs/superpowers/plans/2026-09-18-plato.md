# T1.3 Plato on Vercel Python + Neon — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run `KalpKan/Plato` (Flask course-outline → .ics converter) as a single Vercel Python function at `https://plato.kalpkan.com`, backed by a Neon Postgres database named `plato`, with PostHog analytics, a health route, a non-developer README, and the ops skill updated.

**Architecture:** Flask stays a WSGI app exposed as `app` from `src/app.py` (declared via `[tool.vercel] entrypoint = "src.app:app"`); Vercel routes every request to it. All state between requests lives in the signed session cookie (only `pdf_hash`, `pdf_filename`, `session_id`, `user_choices`) plus the Neon `extraction_cache` / `user_choices` tables keyed by `pdf_hash`; nothing is written outside `/tmp`, and the `.ics` is generated and streamed back in the same request that asks for it. Static files move to `public/static` so Vercel's CDN serves them.

**Tech Stack:** Python 3.12 (Vercel), Flask 3, pdfplumber + PyMuPDF, icalendar, psycopg2-binary (Neon pooled URL), posthog (server events), posthog-js snippet through a `/ingest` reverse-proxy route, Vercel CLI 59, Neon API v2, Cloudflare API v4.
