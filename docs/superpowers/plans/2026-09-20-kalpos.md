# KalpOS front end — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Replace the hub's channel-map front end with KalpOS: a black lock screen that unlocks into a frosted-glass desk whose folders open draggable windows, with the projects registry, health checks, case studies, analytics and OG image wired underneath exactly as today.

**Architecture:** One client root (`components/kalpos/KalpOS.tsx`) owns the boot stage (lock → unlocking → desk) and a pure window reducer (`lib/windows.ts`); the desk renders beneath the lock from the first paint so the unlock is a crossfade. The registry maps to tiles through pure functions in `lib/tiles.ts`; the browser health check (`lib/signal.ts`) feeds each tile's mark. Case studies keep their content files and showcase components, restyled to the window idiom and rendered inside a window (server-rendered on `/projects/<slug>` for SEO and the existing test, code-split on demand from the desk). Below 768 px the desk folds into the 1e phone sheet.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, one plain CSS file (`app/kalpos.css`) carrying the mock's values verbatim, Tailwind 4 kept for the showcase components, `@phosphor-icons/react` (duotone), vitest + jsdom, PostHog via the existing provider.

**Spec:** `docs/superpowers/specs/2026-09-20-kalpos-frontend-design.md`. **Design source:** `docs/design/KalpOS-Mockups.dc.html` cards 3c, 3b, 2a, 2c, 2d, 2e, 1e (serve `docs/design/` with `python3 -m http.server 8932`).

## Global Constraints

- The mock's CSS values win: copy colours, radii, blur, shadows, font sizes and timings from the card markup verbatim (they are listed per task below). No substituted aesthetic.
- Fonts: chrome uses the system stack `-apple-system,BlinkMacSystemFont,'SF Pro Display','SF Pro Text','Helvetica Neue',Helvetica,sans-serif`; Geist Mono (already self-hosted at `app/fonts/GeistMono-400-latin.woff2`) where card 1e uses it. Source Serif 4 is linked by the mock's head but used by none of the composed cards' markup, so it is not shipped (see "As executed").
- Icons: `@phosphor-icons/react`, `weight="duotone"`.
- Black is the only dark surface (lock screen + boot). No dark desk. Remove the old dark-mode token block.
- One motion curve for geometry: `cubic-bezier(.2,.8,.2,1)`; opacity/blur use plain `ease`. `prefers-reduced-motion`: boot = 400 ms crossfade, windows appear in place, dock does not magnify, trace pre-drawn.
- Accessibility: folders/tiles/dock items are `<button>`/`<a>`; windows are `role="dialog"` with a focus trap and Esc to close; skip-to-content link first in the DOM.
- Keep working: PostHog provider + `/ingest` rewrites, `project_card_clicked`, add `window_opened {slug}` and `unlocked`; `app/api/status/[slug]` + `lib/health.ts`; `content/projects/*` + `components/showcase/*`; `app/opengraph-image.tsx` (art updated to the KalpOS mark); `lib/site.ts` (extended, all new fields optional, empty = hidden); `vercel.json`.
- Tests: `npx vitest run --pool=forks --maxWorkers=1` stays green; existing `lib/`, `content/`, showcase and page tests keep passing (only `components/ContactRow.test.tsx` is replaced by `lib/contact.test.ts` because the component is folded into the Contact window).
- Lighthouse performance ≥ 0.90 on `/`. No layout shift on the clock (inline script fills the time before first paint, `suppressHydrationWarning`).
- Phone sheet at widths ≤ 768 px (the verification list checks 768 as a phone width); desk from 769 px.
- Spend $0; no new services; no secrets in git; commit messages end with `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`.

## As executed (deviations from the mock/spec, with reasons)

1. **Visits count omitted** (menubar "1,284 visits" in 2c/2d). There is no cheap public PostHog endpoint (a count needs the personal API key server-side) and the spec says omit rather than fake. The menubar right side is Résumé pill (when set) · wifi · battery · clock.
2. **Source Serif 4 not shipped.** The mock's `<head>` links it and card 3b's caption mentions it, but none of the composed cards' markup (3c, 2c, 2d, 1e) sets it; every text node uses the system stack. Copying the markup verbatim wins; Geist Mono (already self-hosted) is the only web font.
3. **Phone breakpoint ≤ 768 px** (spec table says "< 768 px", the verification list checks 768 as a phone width). 768 shows the 1e sheet; the desk starts at 769.
4. **Lock clock 96 px below 480 px** and the caption reads "tap to unlock" on coarse pointers (the 128 px clock spans a 390 px screen edge to edge; on a phone the pill is a button). Mock only shows the 1040 px lock.
5. **Windows never run under the dock** (`max-height: 100dvh − 202px`, bodies scroll). 2d's window is taller than its card; on a real 900 px viewport the grid would sit under the dock.
6. **Window position**: 2d puts the Projects window at left 150 of a 1040 desk; here the first window is centred (CSS `clamp`) at top 86 and later windows cascade 28 px, so it works at every width without JS.
7. **Browser health check does not abort** (a fetch wrapper on the page, posthog-js session replay, turns an aborted request into an unhandled rejection); it races an 8 s timeout instead. Same result, no console noise.
8. **Trash / Hobbies / About / Contact / Music / Terminal windows** are not mocked; they reuse the window frame, `.kos-body` type and the tokens. Terminal shows the health round (`GET /api/status/<slug> → 200 ok`) so every dock tile does something.
9. **Dock PDF tile and menubar Résumé pill hide while `SITE.resumeUrl` is empty**; the Now-playing icon and widget hide while `SITE.nowPlaying.title` is empty (spec: empty = hidden). The mock shows them filled with placeholders.
10. **Menubar words (File, Edit, View, Go, Window) are decorative** as in the mock; the focused window's title appears after "KalpOS" (2d).
11. **`docs/**` excluded from vitest, tsc and eslint**: `docs/reports/evidence/` holds test/script copies from other repos (they import `../src/form` etc.) and had been failing all three gates on `main`.
12. **`components/ContactRow.tsx` and its test were replaced by `lib/contact.ts` + test**; `Board.tsx`, `marks.tsx` and the Bricolage font were deleted as the spec lists.
13. **Preview deployments are SSO-protected** (team-scoped URL), so Lighthouse ran against the local production build (`next start`) and, after the merge, against production; the Chrome checks ran on the preview through the signed-in browser.
14. **Visit policy changed (2026-09-20, after launch): the lock shows on every plain visit.** The spec's returning-visitor skip (`localStorage["kalpos:visited"]`) meant Kalp never saw his own lock screen again after the first visit. `lib/visitor.ts` is gone; the pre-paint script (`lib/boot.ts` `BOOT_SCRIPT`) now only marks the desk for `/projects/<slug>` and `?desk` (so shared links still land on the content) and removes the stale key. Sequence per visit: boot → lock → desk.
15. **Boot before the lock (card 2a + 3b "Try next") built after launch.** The mark resolves from a 16 px blur in 600 ms over a 180 × 2 px hairline whose fill is real readiness (registry + each health check); minimum 900 ms so it is legible, cap 3 s so a slow endpoint cannot hold the site; the mark exit and the layer fade are 600 ms while the lock fades in. Reduced motion: 400 ms crossfade to the lock. The lock's password field takes focus once the lock is interactive (not on touch).
16. **Startup chime (Kalp, 2026-09-20).** Synthesised, never a recording (Apple's chime is a trademark): `lib/chime.ts`. Plays once per page load, at the boot mark when the tab already allows audio, otherwise on the unlock gesture 400 ms later; `chime_played {at}`; speaker toggle in the menubar persisted as `kalpos:mute`. `data-chime` on `.kos` says where it sounded.

The pointer is captured once the 4 px threshold is crossed. The second click of a double-click on a desk icon is ignored (400 ms). `test/render.tsx` `realClick()` models the browser's capture path so the tests click through it.
