# T4.1 Showcase / Case-Study Pages — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every `type: "showcase"` entry in `projects.json` renders a real case-study page at `/projects/<slug>` on the hub (hero, problem, how it works with an SVG architecture diagram, photo gallery, app-screen carousel, video, tech list, repo link, status line), with true prose written from each repo, labelled placeholders where media is missing, and the RC-car repo purge opened as a PR.

**Architecture:** Content is a typed TypeScript object per project in `content/projects/<slug>.ts` (no MDX dependency; the type in `content/case-study.ts` is the contract). `content/projects/index.ts` maps slug → content and `app/projects/[slug]/page.tsx` renders it through `components/showcase/*`. Images are static imports under `public/images/projects/<slug>/` (WebP ≤ 300 KB, checked by a vitest test) served through `next/image`; videos are never committed (YouTube unlisted / R2 URL, or a placeholder block). A registry `status: "coming"` showcase keeps the old placeholder page so nothing unfinished is published.

**Tech Stack:** Next.js 16 App Router (static params), TypeScript, Tailwind 4 tokens from `app/globals.css` / `DESIGN.md`, `next/image`, `sharp` (already a dependency of Next) for WebP conversion, OpenCV (`~/projects/microtubules/.venv`) for video poster frames, vitest `--pool=forks --maxWorkers=1`, posthog-js via the existing `lib/track.ts`.

**Spec:** `docs/hosting-plan.md` §1 (Showcase table) and §6 "Showcase pages"; task brief T4.1 (Definition of done).
