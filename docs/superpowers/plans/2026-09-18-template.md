# T1.2 New-project template repo — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public GitHub template repo `KalpKan/portfolio-template` (local `~/projects/portfolio-template`) from which any new hosted project on kalpkan.com starts: Next.js App Router + TS + Tailwind, vitest, zod, a schema-scoped Supabase client, migration 0001, `/api/health`, PostHog exactly as the hub does it, the "part of kalpkan.com" footer, CI, a non-developer README, proven by a throwaway end-to-end spin-up in under 15 minutes.

**Architecture:** One Next.js 16 app scaffolded by `create-next-app`, with three small library modules (`lib/supabase.ts`, `lib/posthog.ts` + `lib/posthog-rewrites.ts` + `lib/track.ts`, `lib/health.ts`) each with a vitest file. Environment-driven: with no env set the app runs, health answers `db: "skipped"`, analytics is a no-op. The Supabase client is created lazily from `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_APP_SCHEMA`. Migration 0001 uses the literal placeholder schema name `__APP__` which the README tells the user to replace (`sed`).

**Tech Stack:** Next.js 16.3.5 (App Router, TypeScript, Tailwind 4), React 19, `@supabase/supabase-js` 2.x, `posthog-js`, `zod` 4, `vitest` 5 + jsdom, ESLint 9 (`eslint-config-next`), GitHub Actions, Vercel CLI 59 (`npx vercel@latest`, scope `kks-projects-2edcb11a`), `gh` (KalpKan).

**Spec:** T1.2 definition of done (workflow task text) + `/Users/kalp/projects/portfolio/docs/hosting-plan.md` §6 "Reusable new project template", §6 "Analytics", §7 row 4b, §10; analytics contract `/Users/kalp/projects/portfolio/docs/analytics.md`; runbook "Add a schema to Supabase Project B" in `skills/portfolio-ops/runbooks.md`.
