# T2.1 — PlantWater / "Plant It" repaired and live at plantit.kalpkan.com

_Written 2026-09-18 by the T2.1 worker. Bite-sized, checkbox per step; ticked as executed. Source: `docs/hosting-plan.md` §1, §6 (database plan item 7), §7 item 7; goal-mode appendix Phase 2._

**Goal:** `KalpKan/PlantWater` becomes one Vercel Hobby project `plantit` (CRA static frontend + Express as the `/api` serverless function), Firebase stays on Spark (Firestore, RTDB, Google Auth on project `plant-it-5e2fc`), plant photos go to Supabase Storage bucket `plantit-photos` in Project B, a visitor can use the whole app with no hardware (simulated sensor + "Water now"), and every paid API call is capped per day with a canned fallback. $0.

**Decisions (made, not asked):**
- Repo layout stays `frontend/` + `backend/`; a root `package.json` owns the backend deps and the Vercel build; `api/index.js` exports the Express app. One repo, one Vercel project.
- `sharp` first (Vercel's Linux builder installs `@img/sharp-linux-x64` from the lockfile); switch to `jimp` only if the deploy fails. The README records which one shipped.
- Firebase Admin credentials come from the service-account file Kalp already has locally (copied to `~/.config/portfolio-ops/`, never into the repo) and live in Vercel env as `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`.
- Pl@ntNet / OpenAI keys are not on this machine: the app ships a demo path (bundled lookup of 5 common plants, deterministic per photo) and STATUS.md gets a "Needs Kalp" item naming the two env vars.
- The old per-user lifetime cap of 2 identifications is replaced by the global per-day spend guard (50/day each for Pl@ntNet and OpenAI, Firestore counter), so visitors are never locked out and Kalp is never billed beyond the free tiers.
